~ $ winget install GitHub.GitHubDesktop

GitHub Desktop.

# pros
  • Simplest of all: ideal for newcomers
  • MIT, maintained by GitHub, frequent releases
  • Drag & drop cherry-pick, squash, reorder
  • PR status and CI checks for GitHub repos
  • Works with any remote, GitLab included
# cons
  • No commit graph: one branch at a time
  • No merge editor: picks a side or opens your editor
  • Integrations: GitHub only
  • No Linux build (community fork only)
  • Power users will hit the ceiling fast
~ $ brew install --cask sourcetree

Sourcetree.

# pros
  • Closest look and feel to GitKraken
  • Full graph, interactive rebase, stash, tags
  • Git-flow, Git LFS, submodules built in
  • Accounts for Bitbucket, GitHub, GitLab
  • Free, Atlassian-backed, very widespread
# cons
  • No Linux, and none on the roadmap
  • Two codebases: Windows and Mac differ
  • Known to be slow on large repos
  • No merge editor: external tool needed
  • Closed source, slow pace of development
C:\src> choco install gitextensions

Git Extensions.

# pros
  • Mature (since 2008), GPL, active project
  • Exposes almost all of Git: graph, rebase, bisect…
  • Fast on big histories
  • Scripts and plugins, Visual Studio integration
  • Pairs with KDiff3 or any merge tool
# cons
  • Windows only since v4
  • Dense, dated interface
  • No PR or issue integration out of the box
  • Built for people who already know Git

GitButler: pros and cons.

# pros
  • Windows, macOS and Linux, free
  • Stacked branches and PRs, GitHub and GitLab
  • Undo anything: operation timeline
  • AI commit messages and branch names
  • The most modern UX of the free tools
# cons
  • Different mental model: training needed
  • Still 0.x, fast-moving
  • Not OSI open source (non-compete clause)
  • Owns the working copy: mixing tools is awkward
  • No classic full commit graph
~/app $ lazygit

lazygit: the terminal.

# pros
  • Most popular Git client on GitHub: 83k stars
  • Fastest interactive rebase there is: one key each
  • Line-by-line staging, custom commands
  • Undo with z, runs over SSH, every OS
  • MIT, very active: release this week
# cons
  • Terminal only: a hard sell for some
  • Keyboard shortcuts to learn
  • Graph is ASCII, no drag & drop
  • Conflicts: pick hunks, no 3-way editor
  • PRs: opens the browser
# also in the terminal: gitui (Rust, MIT) · tig (history browser, GPL)
~/app $ code .

VS Code, as is.

# pros
  • Already installed, zero rollout
  • Built-in Source Control Graph
  • Good 3-way merge editor
  • Free PR extensions: GitHub, GitLab
  • GitLens Community stays free: blame, history
# cons
  • Graph is basic: no drag & drop
  • GitLens Pro features leave with GitKraken
  • Git Graph extension: unmaintained since 2021
  • Rebase, reset, reflog: back to the command line
  • Only for people who use VS Code
~/app $ idea .

JetBrains IDEs.

# pros
  • Already paid for if the team uses them
  • Best-in-class 3-way merge
  • Full log graph, interactive rebase dialog
  • Changelists, shelve, partial commits
  • PR review for GitHub and GitLab
# cons
  • Only for JetBrains users
  • Heavy to open just to do Git
  • One project window at a time
  • Proprietary

What we would lose.

# one tool for all
Same app on Win, Mac, Linux. One way to train, document and help.
# drag & drop graph
Merge, rebase and cherry-pick by mouse. Only Sourcetree and Fork come close.
# PRs in the client
Launchpad, issues, Jira. Back to the browser or the IDE.
# workspaces
Fetch, branch and check out across many repos at once.
# GitLens Pro & AI
Commit Graph in VS Code, AI commits, PR summaries, conflict help.
# vendor
Support SLA, SSO, central license admin, audit logs.

Switching is not free.

Screenshots, guides and onboarding checklists to rewrite.

Teams that drop the GUI often understand Git better.
